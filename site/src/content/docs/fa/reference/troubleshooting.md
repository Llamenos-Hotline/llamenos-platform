این راهنما مشکلات رایج و راه‌حل‌های آنها را در همه حالت‌های استقرار و پلتفرم‌های Llámenos پوشش می‌دهد.

## مشکلات استقرار Docker

### کانتینرها شروع نمی‌شوند

**متغیرهای محیطی گمشده:**

Docker Compose همه سرویس‌ها را در راه‌اندازی اعتبارسنجی می‌کند، حتی آنهایی که پروفایل شده‌اند. اگر خطاهایی درباره متغیرهای گمشده می‌بینید، مطمئن شوید فایل `.env` شما شامل همه مقادیر مورد نیاز است:

```bash
# الزامی در .env برای Docker Compose
PG_PASSWORD=your_postgres_password
STORAGE_ACCESS_KEY=your_rustfs_access_key
STORAGE_SECRET_KEY=your_rustfs_secret_key
HMAC_SECRET=your_hmac_secret
ARI_PASSWORD=your_ari_password       # حتی اگر از Asterisk استفاده نمی‌کنید الزامی است
BRIDGE_SECRET=your_bridge_secret     # حتی اگر از Asterisk استفاده نمی‌کنید الزامی است
ADMIN_PUBKEY=your_admin_hex_pubkey
```

حتی اگر از پل Asterisk استفاده نمی‌کنید، Docker Compose تعریف سرویس آن را اعتبارسنجی می‌کند و `ARI_PASSWORD` و `BRIDGE_SECRET` باید تنظیم شوند.

**تعارض پورت‌ها:**

اگر پورتی قبلاً در حال استفاده است، بررسی کنید کدام فرآیند آن را در اختیار دارد:

```bash
# بررسی کنید چه چیزی از پورت 8787 (Worker) استفاده می‌کند
sudo lsof -i :8787

# بررسی کنید چه چیزی از پورت 5432 (PostgreSQL) استفاده می‌کند
sudo lsof -i :5432

# بررسی کنید چه چیزی از پورت 9000 (RustFS) استفاده می‌کند
sudo lsof -i :9000
```

فرآیند متعارض را متوقف کنید یا نگاشت پورت را در `docker-compose.yml` تغییر دهید.

### خطاهای اتصال پایگاه داده

اگر برنامه نمی‌تواند به PostgreSQL متصل شود:

- `PG_PASSWORD` در `.env` را تأیید کنید که با آنچه هنگام اولین ایجاد کانتینر استفاده شده مطابقت دارد
- بررسی کنید که کانتینر PostgreSQL سالم است: `docker compose ps`
- اگر رمز عبور تغییر کرده است، ممکن است نیاز به حذف volume و ایجاد مجدد داشته باشید: `docker compose down -v && docker compose up -d`

### رله Strfry متصل نمی‌شود

رله WebSocket (رله WebSocket) یک سرویس اصلی است، نه اختیاری. اگر رله در حال اجرا نیست:

```bash
# وضعیت رله را بررسی کنید
docker compose logs WebSocket relay

# رله را راه‌اندازی مجدد کنید
docker compose restart WebSocket relay
```

اگر رله شروع به کار نمی‌کند، تعارض پورت 7777 یا مجوزهای ناکافی در دایرکتوری داده را بررسی کنید.

### خطاهای ذخیره‌سازی RustFS / S3

- `STORAGE_ACCESS_KEY` و `STORAGE_SECRET_KEY` را تأیید کنید که صحیح هستند
- بررسی کنید که کانتینر RustFS در حال اجراست: `docker compose ps rustfs`
- به کنسول RustFS در `http://localhost:9001` دسترسی پیدا کنید تا ایجاد bucket را تأیید کنید

## مشکلات استقرار Cloudflare

### خطاهای Durable Object

**«Durable Object یافت نشد» یا خطاهای binding:**

- `bun run deploy` را اجرا کنید (هرگز `wrangler deploy` را مستقیماً اجرا نکنید) تا اطمینان حاصل شود bindingهای DO صحیح هستند
- `wrangler.jsonc` را برای نام‌های کلاس DO صحیح و bindingها بررسی کنید
- پس از افزودن یک DO جدید، باید قبل از در دسترس قرار گرفتن آن را مستقر کنید

**محدودیت‌های ذخیره‌سازی DO:**

Cloudflare Durable Objects دارای محدودیت 128 کیلوبایت برای هر جفت کلید-مقدار هستند. اگر خطاهای ذخیره‌سازی می‌بینید:

- اطمینان حاصل کنید که محتوای یادداشت از محدودیت تجاوز نمی‌کند (یادداشت‌های بسیار بزرگ با پیوست‌های زیاد)
- بررسی کنید که envelopeهای ECIES تکراری نمی‌شوند

### خطاهای Worker (پاسخ‌های 500)

لاگ‌های Worker را بررسی کنید:

```bash
bunx wrangler tail
```

علل رایج:
- رازهای گمشده (از `bunx wrangler secret list` برای تأیید استفاده کنید)
- فرمت نادرست `ADMIN_PUBKEY` (باید 64 کاراکتر hex باشد، بدون پیشوند `npub`)
- محدودیت نرخ در tier رایگان (1000 درخواست/دقیقه در Workers Free)

### استقرار با خطای «Pages deploy» شکست می‌خورد

هرگز `wrangler pages deploy` یا `wrangler deploy` را مستقیماً اجرا نکنید. همیشه از اسکریپت‌های `package.json` ریشه استفاده کنید:

```bash
bun run deploy          # همه چیز را مستقر کنید (برنامه + سایت بازاریابی)
bun run deploy:site     # فقط سایت بازاریابی را مستقر کنید
```

اجرای `wrangler pages deploy dist` از دایرکتوری اشتباه، ساخت Vite برنامه را به جای سایت Astro به Pages مستقر می‌کند و سایت بازاریابی را با خطاهای 404 خراب می‌کند.

## مشکلات برنامه دسکتاپ

### به‌روزرسانی خودکار کار نمی‌کند

برنامه دسکتاپ از Tauri updater برای بررسی نسخه‌های جدید استفاده می‌کند. اگر به‌روزرسانی‌ها شناسایی نمی‌شوند:

- اتصال اینترنت خود را بررسی کنید
- تأیید کنید که endpoint به‌روزرسانی قابل دسترسی است: `https://github.com/rhonda-rodododo/llamenos-platform/releases/latest/download/latest.json`
- در Linux، به‌روزرسانی خودکار AppImage نیاز به مجوز نوشتن فایل در دایرکتوری خود دارد
- در macOS، برنامه باید در `/Applications` باشد (نه در حال اجرا مستقیماً از DMG)

برای به‌روزرسانی دستی، آخرین نسخه را از صفحه [دانلود](/download) دریافت کنید.

### باز کردن با PIN شکست می‌خورد

اگر PIN شما در برنامه دسکتاپ رد می‌شود:

- مطمئن شوید PIN صحیح را وارد می‌کنید (هیچ گزینه «فراموشی PIN» برای بازیابی وجود ندارد)
- PINها در صورت وجود حروف به بزرگی و کوچکی حساس هستند
- اگر PIN خود را فراموش کرده‌اید، باید nsec خود را دوباره وارد کنید تا PIN جدیدی تنظیم کنید. یادداشت‌های رمزنگاری شده شما همچنان در دسترس هستند زیرا به هویت شما گره خورده‌اند، نه PIN شما
- Tauri Stronghold nsec شما را با کلید مشتق از PIN (PBKDF2) رمزنگاری می‌کند. یک PIN اشتباه رمزگشایی نامعتبر تولید می‌کند — برنامه این را با تأیید کلید عمومی مشتق شده تشخیص می‌دهد

### بازیابی کلید

اگر به دستگاه خود دسترسی ندارید:

۱. از nsec خود (که باید در یک مدیر رمز عبور ذخیره کرده باشید) برای ورود در دستگاه جدید استفاده کنید
۲. اگر یک passkey WebAuthn ثبت کرده‌اید، می‌توانید به جای آن در دستگاه جدید از آن استفاده کنید
۳. یادداشت‌های رمزنگاری شده شما سمت سرور ذخیره می‌شوند — پس از ورود با همان هویت، می‌توانید آنها را رمزگشایی کنید
۴. اگر هر دو nsec و passkey خود را گم کرده‌اید، با مدیر خود تماس بگیرد. آنها نمی‌توانند nsec شما را بازیابی کنند، اما می‌توانند یک هویت جدید برای شما ایجاد کنند. یادداشت‌های رمزنگاری شده برای هویت قدیمی شما دیگر توسط شما قابل خواندن نخواهند بود

### برنامه شروع نمی‌شود (پنجره خالی)

- بررسی کنید که سیستم شما حداقل نیازمندی‌ها را برآورده می‌کند (به [دانلود](/download) مراجعه کنید)
- در Linux، اطمینان حاصل کنید WebKitGTK نصب شده است: `sudo apt install libwebkit2gtk-4.1-0` (Debian/Ubuntu) یا معادل آن
- سعی کنید از ترمینال راه‌اندازی کنید تا خروجی خطا را ببینید: `./llamenos` (AppImage) یا لاگ‌های سیستم را بررسی کنید
- اگر از Wayland استفاده می‌کنید، به عنوان fallback با `GDK_BACKEND=x11` امتحان کنید

### تضاد نمونه واحد

Llámenos حالت نمونه واحد را اجرا می‌کند. اگر برنامه می‌گوید قبلاً در حال اجراست اما پنجره را پیدا نمی‌کنید:

- فرآیندهای پس‌زمینه را بررسی کنید: `ps aux | grep llamenos`
- هر فرآیند یتیم را خاتمه دهید: `pkill llamenos`
- در Linux، یک فایل قفل stale را بررسی کنید و در صورت خرابی برنامه آن را حذف کنید

## مشکلات برنامه موبایل

### شکست‌های provisioning

برای عیب‌یابی دقیق provisioning به [راهنمای موبایل](/docs/mobile-guide#troubleshooting-mobile-issues) مراجعه کنید.

علل رایج:
- QR code منقضی شده (توکن‌ها پس از 5 دقیقه منقضی می‌شوند)
- عدم اتصال اینترنت در هیچ‌یک از دستگاه‌ها
- برنامه دسکتاپ و برنامه موبایل در حال اجرای نسخه‌های پروتکل متفاوت

### اعلان‌های فشاری نمی‌رسند

- مجوزهای اعلان را در تنظیمات سیستم‌عامل تأیید کنید
- در Android، بررسی کنید که بهینه‌سازی باتری برنامه را در پس‌زمینه خاتمه نمی‌دهد
- در iOS، بررسی کنید که Background App Refresh برای Llámenos فعال است
- بررسی کنید که یک شیفت فعال دارید و در استراحت نیستید

## مشکلات تلفنی

### پیکربندی webhook Twilio

اگر تماس‌ها به داوطلبان مسیریابی نمی‌شوند:

۱. webhook URLهای خود را در کنسول Twilio تأیید کنید:
   - Voice webhook: `https://your-worker.your-domain.com/telephony/incoming` (POST)
   - Status callback: `https://your-worker.your-domain.com/telephony/status` (POST)
۲. بررسی کنید که اعتبارنامه‌های Twilio در تنظیمات شما با کنسول مطابقت دارد:
   - Account SID
   - Auth Token
   - شماره تلفن (باید شامل کد کشور باشد، مثلاً `+1234567890`)
۳. دیباگر Twilio را برای خطاها بررسی کنید: [twilio.com/console/debugger](https://www.twilio.com/console/debugger)

### راه‌اندازی شماره

- شماره تلفن باید یک شماره متعلق به Twilio یا یک شناسه تماس‌گیرنده تأیید شده باشد
- برای توسعه محلی، از یک Cloudflare Tunnel یا ngrok برای در معرض دید قرار دادن Worker محلی خود به Twilio استفاده کنید
- تأیید کنید که پیکربندی Voice شماره به webhook URL شما اشاره دارد، نه به TwiML Bin پیش‌فرض

### تماس‌ها متصل می‌شوند اما صدا ندارند

- اطمینان حاصل کنید که سرورهای رسانه ارائه‌دهنده تلفنی می‌توانند به تلفن داوطلب برسند
- مشکلات NAT/firewall که ترافیک RTP را مسدود می‌کند را بررسی کنید
- اگر از WebRTC استفاده می‌کنید، تأیید کنید که سرورهای STUN/TURN به درستی پیکربندی شده‌اند
- برخی VPNها ترافیک VoIP را مسدود می‌کنند — بدون VPN امتحان کنید

### پیام‌های SMS/WhatsApp نمی‌رسند

- webhook URLهای پیام‌رسانی را در کنسول ارائه‌دهنده خود تأیید کنید
- برای WhatsApp، اطمینان حاصل کنید که توکن تأیید webhook Meta با تنظیمات شما مطابقت دارد
- بررسی کنید که کانال پیام‌رسانی در **تنظیمات مدیر > کانال‌ها** فعال است
- برای Signal، تأیید کنید که پل signal-cli در حال اجراست و برای ارسال به webhook شما پیکربندی شده است

## خطاهای رمزنگاری

### خطاهای عدم تطابق کلید

**«رمزگشایی ناموفق» یا «کلید نامعتبر» هنگام باز کردن یادداشت‌ها:**

- این معمولاً به این معناست که یادداشت برای هویتی متفاوت از آنچه شما با آن وارد شده‌اید رمزنگاری شده است
- تأیید کنید که از nsec صحیح استفاده می‌کنید (npub خود را در تنظیمات بررسی کنید که با آنچه مدیر می‌بیند مطابقت دارد)
- اگر اخیراً هویت خود را دوباره ایجاد کرده‌اید، یادداشت‌های قدیمی رمزنگاری شده برای کلید عمومی قبلی شما با کلید جدید قابل رمزگشایی نخواهند بود

**«امضای نامعتبر» هنگام ورود:**

- nsec ممکن است خراب شده باشد — سعی کنید آن را از مدیر رمز عبور خود دوباره وارد کنید
- اطمینان حاصل کنید که nsec کامل جای‌گذاری شده است (با `nsec1` شروع می‌شود، 63 کاراکتر در کل)
- فاصله یا کاراکتر newline اضافی را بررسی کنید

### شکست‌های تأیید امضا

اگر رویدادهای hub تأیید امضا را ناموفق می‌کنند:

- بررسی کنید که ساعت سیستم همگام‌سازی شده است (NTP). انحراف ساعت بزرگ می‌تواند باعث مشکلات timestamp رویداد شود
- تأیید کنید که رله WebSocket رویدادها را از pubkeyهای ناشناس relay نمی‌کند
- برنامه را راه‌اندازی مجدد کنید تا لیست فعلی اعضای hub را دوباره واکشی کند

### خطاهای envelope ECIES

**«باز کردن کلید ناموفق» هنگام رمزگشایی یادداشت:**

- envelope ECIES ممکن است با یک کلید عمومی نادرست ایجاد شده باشد
- این می‌تواند زمانی رخ دهد که مدیر یک داوطلب با خطای تایپی در pubkey اضافه کرده باشد
- مدیر باید کلید عمومی داوطلب را تأیید کند و در صورت لزوم دوباره دعوت کند

**«طول ciphertext نامعتبر»:**

- این نشان‌دهنده خرابی داده است، احتمالاً از یک پاسخ شبکه truncate شده
- عملیات را دوباره امتحان کنید. اگر ادامه داشت، داده‌های رمزنگاری شده ممکن است به طور دائمی خراب شده باشند
- مشکلات پراکسی یا CDN که ممکن است بدنه پاسخ‌ها را truncate کنند را بررسی کنید

### خطاهای کلید hub

**«رمزگشایی رویداد hub ناموفق»:**

- کلید hub ممکن است از آخرین اتصال شما چرخانده شده باشد
- برنامه را ببندید و دوباره باز کنید تا آخرین کلید hub را واکشی کنید
- اگر اخیراً از hub حذف شده‌اید و دوباره اضافه شده‌اید، کلید ممکن است در طول غیبت شما چرخانده شده باشد
