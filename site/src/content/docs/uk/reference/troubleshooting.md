Цей посібник охоплює поширені проблеми та їхні рішення для всіх режимів розгортання Llamenos та платформ.

## Проблеми з розгортанням Docker

### Контейнери не запускаються

**Відсутні змінні середовища:**

Docker Compose валідує всі сервіси під час запуску, навіть ті, що належать до профілів. Якщо ви бачите помилки про відсутні змінні, переконайтеся, що ваш файл `.env` містить усі необхідні значення:

```bash
# Обов'язково в .env для Docker Compose
PG_PASSWORD=your_postgres_password
STORAGE_ACCESS_KEY=your_rustfs_access_key
STORAGE_SECRET_KEY=your_rustfs_secret_key
HMAC_SECRET=your_hmac_secret
ARI_PASSWORD=your_ari_password       # Обов'язково, навіть якщо не використовуєте Asterisk
BRIDGE_SECRET=your_bridge_secret     # Обов'язково, навіть якщо не використовуєте Asterisk
ADMIN_PUBKEY=your_admin_hex_pubkey
```

Навіть якщо ви не використовуєте міст Asterisk, Docker Compose валідує його визначення сервісу та вимагає встановлення `ARI_PASSWORD` та `BRIDGE_SECRET`.

**Конфлікти портів:**

Якщо порт вже використовується, перевірте, який процес його утримує:

```bash
# Перевірте, що використовує порт 8787 (Worker)
sudo lsof -i :8787

# Перевірте, що використовує порт 5432 (PostgreSQL)
sudo lsof -i :5432

# Перевірте, що використовує порт 9000 (RustFS)
sudo lsof -i :9000
```

Зупиніть конфліктний процес або змініть відображення порту в `docker-compose.yml`.

### Помилки підключення до бази даних

Якщо додаток не може підключитися до PostgreSQL:

- Перевірте, що `PG_PASSWORD` в `.env` відповідає тому, що використовувалося при першому створенні контейнера
- Перевірте, що контейнер PostgreSQL здоровий: `docker compose ps`
- Якщо пароль було змінено, можливо, потрібно видалити том і перестворити: `docker compose down -v && docker compose up -d`

### Ретранслятор strfry не підключається

Ретранслятор WebSocket — це основний сервіс, а не опціональний. Якщо ретранслятор не працює:

```bash
# Перевірте статус ретранслятора
docker compose logs WebSocket relay

# Перезапустіть ретранслятор
docker compose restart WebSocket relay
```

Якщо ретранслятор не запускається, перевірте конфлікти порту 7777 або недостатні дозволи на каталог даних.

### Помилки RustFS / S3-сховища

- Перевірте, що `STORAGE_ACCESS_KEY` та `STORAGE_SECRET_KEY` правильні
- Перевірте, що контейнер RustFS працює: `docker compose ps rustfs`
- Отримайте доступ до консолі RustFS за адресою `http://localhost:9001`, щоб перевірити створення бакету

## Проблеми з розгортанням Cloudflare

### Помилки Durable Object

**"Durable Object not found" або помилки прив'язки:**

- Запустіть `bun run deploy` (ніколи `wrangler deploy` напряму), щоб переконатися, що прив'язки DO правильні
- Перевірте `wrangler.jsonc` на правильність імен класів DO та прив'язок
- Після додавання нового DO його потрібно розгорнути, перш ніж він стане доступним

**Обмеження сховища DO:**

Cloudflare Durable Objects мають обмеження 128 КБ на пару ключ-значення. Якщо ви бачите помилки сховища:

- Переконайтеся, що вміст нотаток не перевищує ліміт (дуже великі нотатки з багатьма вкладеннями)
- Перевірте, що конверти ECIES не дублюються

### Помилки Worker (500 відповіді)

Перевірте журнали Worker:

```bash
bunx wrangler tail
```

Поширені причини:
- Відсутні секрети (використовуйте `bunx wrangler secret list` для перевірки)
- Неправильний формат `ADMIN_PUBKEY` (має бути 64 hex-символи, без префікса `npub`)
- Обмеження швидкості на безкоштовному тарифі (1 000 запитів/хвилина на Workers Free)

### Розгортання завершується помилкою "Pages deploy"

Ніколи не запускайте `wrangler pages deploy` або `wrangler deploy` напряму. Завжди використовуйте скрипти з кореневого `package.json`:

```bash
bun run deploy          # Розгорнути все (додаток + маркетинговий сайт)
bun run deploy:site     # Розгорнути лише маркетинговий сайт
```

Запуск `wrangler pages deploy dist` з неправильного каталогу розгортає збірку Vite-додатку на Pages замість Astro-сайту, що ламає маркетинговий сайт із помилками 404.

## Проблеми з настільним додатком

### Автоматичне оновлення не працює

Настільний додаток використовує оновлювач Tauri для перевірки нових версій. Якщо оновлення не виявляються:

- Перевірте підключення до інтернету
- Перевірте, що кінцева точка оновлення доступна: `https://github.com/rhonda-rodododo/llamenos-platform/releases/latest/download/latest.json`
- На Linux автоматичне оновлення AppImage вимагає, щоб файл мав дозволи на запис у своєму каталозі
- На macOS додаток повинен бути в `/Applications` (не запущений напряму з DMG)

Для ручного оновлення завантажте останній реліз із сторінки [Завантаження](/download).

### Розблокування PIN не вдається

Якщо ваш PIN відхиляється в настільному додатку:

- Переконайтеся, що ви вводите правильний PIN (немає функції "забули PIN")
- PIN-коди чутливі до регістру, якщо містять літери
- Якщо ви забули свій PIN, ви повинні повторно ввести свій nsec, щоб встановити новий. Ваші зашифровані нотатки залишаються доступними, оскільки вони прив'язані до вашої ідентичності, а не до PIN
- Tauri Stronghold шифрує ваш nsec ключем, отриманим із PIN (PBKDF2). Неправильний PIN призводить до недійсного розшифрування, а не до повідомлення про помилку — додаток виявляє це, перевіряючи отриманий публічний ключ

### Відновлення ключа

Якщо ви втратили доступ до свого пристрою:

1. Використовуйте свій nsec (який ви повинні були зберегти в менеджері паролів) для входу на новому пристрої
2. Якщо ви зареєстрували ключ WebAuthn, ви можете використовувати його на новому пристрої замість цього
3. Ваші зашифровані нотатки зберігаються на стороні сервера — після входу з тією ж ідентичністю ви можете їх розшифрувати
4. Якщо ви втратили і nsec, і ключ WebAuthn, зверніться до свого адміністратора. Вони не можуть відновити ваш nsec, але можуть створити нову ідентичність для вас. Нотатки, зашифровані для вашої старої ідентичності, більше не будуть доступні для вас

### Додаток не запускається (порожнє вікно)

- Перевірте, що ваша система відповідає мінімальним вимогам (див. [Завантаження](/download))
- На Linux переконайтеся, що встановлено WebKitGTK: `sudo apt install libwebkit2gtk-4.1-0` (Debian/Ubuntu) або еквівалент
- Спробуйте запустити з терміналу, щоб побачити вивід помилок: `./llamenos` (AppImage) або перевірте системні журнали
- Якщо використовуєте Wayland, спробуйте `GDK_BACKEND=x11` як запасний варіант

### Конфлікт єдиного екземпляра

Llamenos забезпечує режим єдиного екземпляра. Якщо додаток каже, що вже працює, але ви не можете знайти вікно:

- Перевірте фонові процеси: `ps aux | grep llamenos`
- Завершіть будь-які осиротілі процеси: `pkill llamenos`
- На Linux перевірте застарілий файл блокування та видаліть його, якщо додаток аварійно завершив роботу

## Проблеми з мобільним додатком

### Помилки підготовки

Див. [Мобільний посібник](/docs/mobile-guide#troubleshooting-mobile-issues) для детального усунення несправностей підготовки.

Поширені причини:
- Прострочений QR-код (токени закінчуються через 5 хвилин)
- Відсутнє підключення до інтернету на будь-якому з пристроїв
- Настільний додаток і мобільний додаток працюють із різними версіями протоколу

### Push-сповіщення не надходять

- Перевірте, що дозволи на сповіщення надані в налаштуваннях ОС
- На Android перевірте, що оптимізація батареї не вбиває додаток у фоновому режимі
- На iOS перевірте, що фонове оновлення додатків увімкнено для Llamenos
- Перевірте, що у вас активна зміна і ви не на перерві

## Проблеми з телефонією

### Конфігурація вебхуків Twilio

Якщо дзвінки не маршрутизуються до волонтерів:

1. Перевірте, що ваші URL-адреси вебхуків правильні в консолі Twilio:
   - Вебхук голосу: `https://your-worker.your-domain.com/telephony/incoming` (POST)
   - Зворотний виклик статусу: `https://your-worker.your-domain.com/telephony/status` (POST)
2. Перевірте, що облікові дані Twilio у ваших налаштуваннях відповідають консолі:
   - Account SID
   - Auth Token
   - Номер телефону (має містити код країни, наприклад, `+1234567890`)
3. Перевірте налагоджувач Twilio на помилки: [twilio.com/console/debugger](https://www.twilio.com/console/debugger)

### Налаштування номера

- Номер телефону повинен бути номером Twilio або підтвердженим caller ID
- Для локальної розробки використовуйте Cloudflare Tunnel або ngrok, щоб відкрити ваш локальний Worker для Twilio
- Перевірте, що конфігурація голосу номера вказує на вашу URL-адресу вебхуку, а не на TwiML Bin за замовчуванням

### Дзвінки з'єднуються, але немає аудіо

- Переконайтеся, що медіа-сервери телефонного провайдера можуть досягти телефону волонтера
- Перевірте проблеми NAT/брандмауера, що блокують трафік RTP
- Якщо використовуєте WebRTC, перевірте, що сервери STUN/TURN налаштовані правильно
- Деякі VPN блокують VoIP-трафік — спробуйте без VPN

### SMS/WhatsApp повідомлення не надходять

- Перевірте, що URL-адреси вебхуків повідомлень налаштовані правильно в консолі вашого провайдера
- Для WhatsApp переконайтеся, що токен верифікації вебхуку Meta відповідає вашим налаштуванням
- Перевірте, що канал повідомлень увімкнено в **Налаштування адміністратора > Канали**
- Для Signal перевірте, що міст signal-cli працює та налаштований для пересилання на ваш вебхук

## Помилки криптографії

### Помилки невідповідності ключів

**"Failed to decrypt" або "Invalid key" при відкритті нотаток:**

- Це зазвичай означає, що нотатка була зашифрована для іншої ідентичності, ніж та, з якою ви увійшли
- Перевірте, що ви використовуєте правильний nsec (перевірте, що ваш npub у Налаштуваннях відповідає тому, що бачить адміністратор)
- Якщо ви нещодавно перестворили свою ідентичність, старі нотатки, зашифровані для вашого попереднього публічного ключа, не будуть розшифровуватися новим ключем

**"Invalid signature" при вході:**

- Nsec може бути пошкоджений — спробуйте повторно ввести його з вашого менеджера паролів
- Переконайтеся, що вставлено повний nsec (починається з `nsec1`, всього 63 символи)
- Перевірте наявність зайвих пробілів або символів нового рядка

### Помилки верифікації підпису

Якщо події хабу не проходять верифікацію підпису:

- Перевірте, що системний годинник синхронізований (NTP). Великий зсув годинника може спричинити проблеми з мітками часу подій
- Перевірте, що ретранслятор WebSocket не пересилає події від невідомих публічних ключів
- Перезапустіть додаток, щоб повторно отримати поточний список членів хабу

### Помилки конверта ECIES

**"Failed to unwrap key" при розшифруванні нотатки:**

- Конверт ECIES може бути створений із неправильним публічним ключем
- Це може статися, якщо адміністратор додав волонтера з помилкою в публічному ключі
- Адміністратор повинен перевірити публічний ключ волонтера та повторно запросити за необхідності

**"Invalid ciphertext length":**

- Це вказує на пошкодження даних, можливо, через обрізану мережеву відповідь
- Повторіть операцію. Якщо проблема зберігається, зашифровані дані можуть бути назавжди пошкоджені
- Перевірте проблеми з проксі або CDN, які можуть обрізати тіла відповідей

### Помилки ключа хабу

**"Failed to decrypt hub event":**

- Ключ хабу може бути змінений з моменту вашого останнього підключення
- Закрийте та відкрийте додаток, щоб отримати останній ключ хабу
- Якщо вас нещодавно видалили та повторно додали до хабу, ключ міг змінитися під час вашої відсутності

## Отримання допомоги

Якщо вашу проблему не розглянуто тут:

- Перевірте [GitHub Issues](https://github.com/rhonda-rodododo/llamenos-platform/issues) на відомі помилки та обхідні шляхи
- Шукайте серед існуючих проблем перед створенням нової
- При повідомленні про помилку вкажіть: ваш режим розгортання (Cloudflare/Docker/Kubernetes), платформу (Настільний/Мобільний) та будь-які повідомлення про помилки з консолі браузера або терміналу
